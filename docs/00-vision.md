# 00 · 愿景、坐标与硬约束

## 0.1 一句话与电梯陈述

**你是一座仙山的掌门。**

三十年前，宗门被魔道灭门，你带着半卷残经在山中重建山门。如今灵气潮汐将起，十二门派虎视眈眈，而你寿元只剩百年。

> 这是一款「会呼吸的宗门」游戏：你经营的不是一堆数字，而是一群人、一座山、一段会被后人写进宗门志的历史。

**电梯陈述（30 秒）**：
> 在浏览器里，经营你的仙山。安排弟子修行与任务，布置灵气与阵法，在门派倾轧中壮大宗门；你也可以亲自下山，以第三人称探索秘境、与人斗法、渡劫飞升。你会老、会死，但你留下的道统会继续。

## 0.2 体验支柱（Design Pillars）

五根支柱，任何系统设计都必须至少服务其中一根；否则砍掉。

### P1 · 山门即角色（Sect as Character）

山门不是背景板，而是可阅读的历史：第一代弟子手植的灵茶树、被雷劫劈开的山崖、为纪念某位长老而立的碑。建筑会旧、会损、会传承。

- 落点：建筑状态与年份绑定；重大事件在场景里留下永久痕迹（疤痕、碑、废墟）。
- 反例：所有玩家到最后都是同一座满级山门。

### P2 · 弟子即故事（People as Story）

每个弟子都有欲望、关系、秘密和寿元。玩家记住的应该是「那个叛逃的弟子」，而不是「一个紫色品质单位」。

- 落点：性格标签 + 关系图 + 隐藏野心 + 可触发的个人事件链。
- 反例：弟子只是数值卡，死了再抽一张。

### P3 · 世界不等你（Living World）

即使玩家挂机，门派也会结盟、开战、覆灭；灵气会涨落；秘境会开合。玩家是在一个已经在运转的世界里做选择，而不是世界的中心。

- 落点：分层模拟（Sim LOD）+ 导演系统 + 世界事件日历。
- 反例：所有事件都围绕玩家刷新。

### P4 · 修为即选择（Cultivation as Choice）

功法、灵根、经脉、道心、因果共同构成 Build。没有唯一最优解，只有取舍与代价。

- 落点：功法槽位 + 经脉图 + 道心状态 + 天劫形态由因果决定。
- 反例：境界=等级，升级=加数值。

### P5 · 一镜到底的东方山水（Painterly AAA）

统一的美术指导优先于多边形数量。用大气、雾、光、构图、镜头运动制造「电影感」，而不是堆 4K 贴图。

- 落点：青绿山水色板、体积雾、丁达尔、宽银幕构图、极简 HUD。
- 反例：写实人脸 + 廉价金红 UI 的「页游修仙」。

## 0.3 「3A」在纯 Web 上的重新定义

### 为什么不能照搬主机 3A

| 维度 | 主机 3A | 纯 Web 现实 |
|------|---------|-------------|
| 资产预算 | 50-200 GB | 首包 < 15 MB，按需流式 |
| 同屏角色 | 数百，GPU Skin + 专用管线 | 100-200，需 VAT/Impostor/Instancing |
| 光照 | 光追 / Lumen | 烘焙 + 屏幕空间 + 少量实时 |
| 团队 | 200-1000 人 | 1-10 人 |
| 内容量 | 30-100 小时手工内容 | 系统生成 + 模板 + 高复用 |

### 我们的「3A」= 四个可度量标准

1. **统一**：任何一帧截图，都能认出是同一款游戏。
2. **密度**：画面里有生活痕迹（晾晒的药材、练剑的弟子、飘动的经幡），不是空场景。
3. **电影感**：关键节点有运镜、有构图、有留白、有音乐进入。
4. **稳定**：目标机型 60fps，波动 < 10%，无加载割裂。

### 性能预算（G1 验证目标）

| 指标 | 桌面独显 1440p | 最低配（M1 / 核显）1080p |
|------|----------------|--------------------------|
| 帧率 | 60 | 30 |
| 帧时间 | 16.6 ms | 33.3 ms |
| Draw calls（主场景） | < 300 | < 180 |
| 三角面 | < 3 M | < 1.2 M |
| 同屏角色 | 200 | 100 |
| 显存（纹理） | < 1.5 GB | < 512 MB |
| 首屏可交互 | < 8 s | < 12 s |
| 首包（gzip） | < 15 MB | 同左 |
| 场景切换 | 无 loading，淡入 < 1 s | 同左 |

> 预算不是口号：每个里程碑都要用真实场景跑一遍，超标即视为未完成。

## 0.4 平台与工程约束

- **纯 Web**：不依赖原生插件；桌面 Chrome / Edge / Safari 最新两个大版本。
- **渲染**：`WebGPURenderer` 优先，`WebGLRenderer` 回退；同一套 TSL 材质尽量双后端可用。
- **移动端**：G4 之后再评估；不作为首发约束。
- **单机优先**：存档本地优先（IndexedDB），云存档可选；联机是 EA 后的赛季玩法。
- **小团队**：必须靠「系统生成内容」而不是「手工堆内容」；所有内容管线要能被 1 个人维护。
- **长期**：项目按 18-24 个月规划，先做可玩的垂直切片，再谈规模。

## 0.5 参考坐标：向谁学什么

| 参考 | 学什么 | 不学什么 |
|------|--------|----------|
| **Crusader Kings III** | 人物驱动的世界模拟、事件叙事、家族/传承、AI 目标 | 过于复杂的 UI、DLC 式内容堆叠 |
| **RimWorld** | AI Storyteller、殖民地经营、涌现故事、模组友好 | 2D 俯视、战斗表现力 |
| **Total War** | 战役层 + 战场层的双尺度、兵种相克、士气 | 历史写实、回合制战役节奏 |
| **Genshin Impact** | 风格化开放世界、元素反应、角色演出、移动端优化 | 抽卡、内容消耗速度、体力制 |
| **Ghost of Tsushima** | 美术指导、引导风、极简 HUD、电影化构图 | 纯动作、线性叙事 |
| **Black Myth: Wukong** | 东方 Boss 演出、UE5 级画面标杆、打击感 | 线性关卡、无经营层 |
| **鬼谷八荒** | 修仙成长线、随机事件、Build 构筑 | 2D 立绘、重复刷、后期数值膨胀 |
| **了不起的修仙模拟器** | 修仙经营、风水灵气、弟子生态 | 像素 2D、UI 门槛、引导缺失 |
| **Elden Ring** | 探索感、地标引导、未知的诱惑 | 高难度、弱叙事、无经营 |
| **Dwarf Fortress** | 深度模拟、涌现叙事、世界生成 | ASCII、学习曲线 |
| **Slay the Spire** | 构筑、决策密度、每局节奏 | 纯卡牌、无世界 |
| **太吾绘卷** | 武侠关系网、世代传承 | UI/引导、系统耦合过深 |

### 三条最重要的借鉴

1. **CK3 的人物模拟** → 我们的弟子：有目标、有记忆、有关系、会自己行动。
2. **RimWorld 的导演** → 我们的世界：按张力投放事件，而不是随机刷。
3. **对马岛的美术指导** → 我们的画面：统一色板 + 引导风 + 极简 HUD，比堆资产更「3A」。

## 0.6 反目标（明确不做）

1. **不做无缝开放世界大地图**：内容成本无底洞，改为「一座可深度经营的山门 + 若干秘境」。
2. **不做照片级人脸/毛发**：改为风格化写实 + 灯光/材质表演。
3. **不做首发 MMO / 实时 PVP**：数值与网络会拖垮一切。
4. **不做纯文字或纯放置**：3A 观感是核心差异点。
5. **不做换皮数值修仙**：没有取舍的升级一律砍。
6. **不承诺 4K/120fps/移动端首发**。

## 0.7 成功标准（G2 垂直切片）

- 新玩家 **10 分钟内**理解：我是掌门，我要在寿元耗尽前变强。
- **30 分钟内**至少经历 3 次有意义取舍（救人/放弃、建丹房/建灵田、收天才/留旧人）。
- 完成 **1 次完整天劫**（战斗 + 抉择），目标机型稳定 60fps。
- **70% 测试者**在 30 分钟结束时表示「想再玩一天」。
- 存档可跨版本迁移，无致命 bug。

> 如果这五条达不到，不扩内容，先改循环。
