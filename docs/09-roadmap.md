# 09 · 路线图、团队与风险

> 小团队做 3A 感游戏，唯一的活路是：**先做最小可玩，再谈规模**。

---

## 9.1 阶段总览

| 阶段 | 周期 | 目标 | 产出 |
|------|------|------|------|
| **G0 策略** | 1 周 | 定方向、定技术、定范围 | 本套文档 |
| **G1 技术验证** | 2 周 | 证明 Web 能跑「山门 + 200 人 + 60fps」 | 可跑的 prototype |
| **G2 垂直切片** | 8 周 | 证明「一天」好玩 | 30-60 分钟可玩 demo |

| **G4 EA** | 6-9 个月 | 上线、打磨、社区 | 20-30 小时 |

> 每个阶段结束都要**重新评估是否继续**，不要因为沉没成本硬撑。

## 9.3 G1 · 技术验证（2 周）

### 目标

用**最少的代码**回答一个问题：**浏览器能不能撑起这个画面和规模？**

### 任务

| 天 | 任务 | 验收 |
|----|------|------|
| D1-2 | 仓库脚手架：Vite + TS + three.js + WebGPU/WebGL 双后端 | 两种后端都能出画面 |
| D3-4 | 地形（clipmap）+ 天空 + 雾 + 一棵树 | 1km² 地形，60fps |
| D5-6 | 第三人称角色控制器 + 相机 + 动画 | 跑/跳/闪避手感 OK |
| D7-8 | 200 NPC 群像（Instancing/VAT）+ 简单 AI 游走 | 200 人不掉到 45fps 以下 |
| D9-10 | 昼夜 + 灯笼 + 体积光 | 夜景可看 |
| D11-12 | 性能面板 + 自动降级 + 包体统计 | 有数据、能降级 |
| D13-14 | 打包、部署、手机/核显测试 | 链接可分享 |

### 验收标准（Exit Criteria）

- [ ] M1 Pro / 1080p / 高画质：**≥ 60fps**，p95 帧时间 < 20ms。
- [ ] M1 / 1080p / 中画质：**≥ 45fps**。
- [ ] 同屏 200 NPC + 地形 + 雾：draw calls < 350。
- [ ] 首包 < 15MB（gzip），首屏可交互 < 10s。
- [ ] WebGPU 与 WebGL2 都能跑，画质差异可接受。
- [ ] 连续运行 30 分钟无内存泄漏（堆增长 < 10%）。

> 如果 G1 不达标：先砍同屏人数/雾/后处理，不要直接上 G2。

### G1 实测结果（2026-11-01，M3 / 1920×1080 / 画质高）

| 指标 | 目标 | 实测 | 结论 |
|------|------|------|------|
| 同屏弟子 | 200 | 200 | ✅ |
| Draw calls | < 350 | 187 | ✅ |
| 三角面 | < 3 M | 0.79 M | ✅ |
| 1080p 帧率 | 60 | 30（headless vsync）/ 44-58（uncapped） | ⚠️ 需真实窗口复测 |
| 冷启动 | < 10 s | 12-15 s | ❌ 需优化 |
| 运行时错误 | 0 | 0 | ✅ |

> 原型见 [`prototype/`](../prototype/README.md)。规模与绘制预算成立；60fps 与冷启动留到 G2 解决。

## 9.7 G2 · 完整垂直切片（剩余）

### 目标

做一段 **30-60 分钟**的完整体验，证明「经营 + 掌门 + 事件」的循环成立。

### 范围（只做这些）

| 模块 | 内容 |
|------|------|
| 山门 | 1 座，8 种建筑，可自由摆放 |
| 弟子 | 7 人，每人有性格/关系/1 条个人事件 |
| 时间 | 1 年（4 季），日循环 + 暂停/加速 |
| 修炼 | 炼气 → 筑基，1 次小突破 + 1 次天劫 |
| 战斗 | 1 个秘境（3 房间）+ 1 个 Boss + 1 场守山战（30v30） |

| 视角 | 宗主俯视 + 掌门第三人称，可切换 |
| 存档 | 自动 + 手动，可读档 |
| 音频 | 1 首主题 + 4 个环境 + 基础战斗音效 |

### 周计划

| 周 | 交付 |
|----|------|
| W1 | 山门场景 + 建造 + 时间系统 |
| W2 | 弟子 + 派遣 + 结算 + 事件框架 |

| W7 | 音频/美术替换 + 性能优化 |

### 验收标准

- [ ] 新玩家 30 分钟内完成「第一天 + 第一次天劫」。

## 9.13 需要拍板的三个问题

### Q1 · 视角

| 选项 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| A. 纯俯视经营 | 便宜、清晰 | 表现力弱 | 备选 |
| B. 纯第三人称 | 沉浸、好宣传 | 经营难做 | 不推荐 |
| C. 双视角（默认俯视，可附身） | 兼顾 | 切换设计难 | ✅ 推荐 |

**建议 C**：默认宗主俯视，`Tab` 附身掌门；山门外强制第三人称。

### Q2 · 战斗节奏

| 选项 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| A. 实时动作 | 爽、好看 | 手残劝退 | 备选 |
| B. 实时 + 战术暂停 | 兼顾策略/动作 | 实现复杂 | ✅ 推荐 |
| C. 回合/自动 | 便宜、适合经营 | 表现力弱 | 备选 |

**建议 B**：默认实时，`T` 慢动作下令；Boss/天劫手动，杂兵可自动。

### Q3 · 联机

| 选项 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| A. 首发单人 | 稳、快 | 少社交 | ✅ 推荐 |
| B. 首发联机 | 长线 | 数值/网络/反挂 | 不推荐 |
| C. 单人 + 异步联机（留言/宗门访客） | 折中 | 设计成本 | 备选 |

**建议 A**：单人首发；EA 后加「异步访客/赛季」；不做实时 PVP。
