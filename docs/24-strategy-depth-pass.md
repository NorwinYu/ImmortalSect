# 24 · 策略纵深与性能收口

> G4 P4：把“每天一个固定事件”改成 **三候选 / 选一 / 跳过**，补上 **建筑驻派、维护费、邻接加成**，同时完成群像 LOD、玩家合批与可回归的冒烟测试。
> 本轮不新增章节，只让已有 12 天主循环更像一个可规划、可取舍的宗门。

## 24.1 每日三候选

日终后不再直接弹出唯一事件，而是生成 **3 张候选**：

| 类型 | 来源 | 作用 |
|---|---|---|
| 主线 / 人物弧 | 下一幕剧本事件，或 9 幕人物线 | 推进章节，可延后 |
| 2 张环境 / 随机事件 | 商队、夜雨、野兽、灵草、访客等 | 提供资源、关系、风险取舍 |

- 玩家 **只能接 1 件**，也可以点 **今日不接**。
- 若没有接主线，主线进入 `storyDeferred`，**明天继续作为主候选出现**，不会被跳过剧情卡死。
- 人物弧同理：弧线旗标没有推进，下一日仍是主候选。
- 候选不消耗行动点；行动点仍用于打坐、炼丹、巡视、外出。
- 候选在日终结算后出现，必须处理或跳过，才能进入下一日。

### 风险、层级与重复保护

- 候选牌显示 `Lv.1-3` 与 **低 / 中 / 高风险**；风险是选项变数的提示。
- 高风险事件的部分选项带 **成功率判定**：`Game.checkChance()` 给出 5-95 的成功率，玩家选该项时用存档内的 `checkSeed` 掷一次；命中失败则结算 `failEffects` 与失败文案，选项列表里直接显示「成功率 61%」。
- 环境事件有 2-3 日冷却；同日不会重复，刚处理过的事件短期内不会立刻再刷。
- 候选使用存档内的 `candidateSeed` 洗牌，读档不会重 roll；种子随存档保存。
- 主线和人物弧不受冷却影响，始终可被延后到下一日。

实现位置：

- `src/game/game.ts`：`buildCandidates()`、`chooseCandidate()`、`skipCandidates()`、`storyDeferred`。
- `src/ui/game-ui.ts`：`showCandidates()`、`showDailyFlow()`。
- `src/game/state.ts` / `saves.ts`：候选字段与旧档兼容。

已实现：**候选种子**（存档内固定，读档不 reroll）、**层级/风险标签**、**2-3 日冷却**。尚未实现的是“等级作为接取门槛”和“成功率结算”；当前事件结果仍由选项 `requires` 与效果确定性决定，风险标签表示选项的变数，不是随机成功率。

## 24.2 建筑岗位

每栋已建成建筑有 **等级数个岗位**，可把任意在册弟子驻派进去：

| 建筑 | 驻派收益 | 对口职业 |
|---|---|---|---|
| 灵田 | 每岗位额外 `等级` 药材/日 | 丹修、杂役 |
| 藏经阁 | 每岗位额外 1 心得/日 | 剑修、体修 |
| 库房 | 每岗位额外 1 灵石/日 | 无灵根、杂役 |
| 膳堂 / 弟子居 | 每岗位额外 1 道心/日 | 医修、杂役 |
| 聚灵阵 | 每岗位额外 2 掌门修为/日 | 剑修、体修 |
| 丹房 | 每岗位额外 1 心得/日 | 丹修 |
| 剑坪 | 每岗位额外 1 声望/日 | 剑修 |

**职业对口**：驻派弟子职业命中建筑对口列表时，额外按 `等级`（灵田）或 `1-2` 点（其他建筑）加成；面板上以「专长」标出。例：苏晚照（丹修）驻派灵田，药材从 `+3` 提升到 `+4`。

### 维护费

- **每 2 个已建成建筑等级，日终消耗 1 灵石**（向上取整）。
- 灵石不足：灵石归零，**道心 -2**，并在结算中提示“建筑失修”。
- 维护费在建筑产出之后结算，避免“先扣钱导致产出为负”的歧义。

### 邻接

同时建成以下组合，日终额外 +1：

| 组合 | 加成 |
|---|---|
| 灵田 + 丹房 | 药材 +1 |
| 剑坪 + 聚灵阵 | 掌门修为 +1 |
| 藏经阁 + 弟子居 | 心得 +1 |
| 膳堂 + 库房 | 道心 +1 |

### UI

建筑面板底部新增 **驻派弟子**：

- 显示 `已驻派 / 岗位数`；
- 每名在册弟子一个按钮，点击驻派，再点召回；
- 岗位满、建筑未建成、弟子离山时按钮禁用；
- 驻派关系写入存档，读档保持。

实现位置：`Game.assignPost()`、`processBuildings()`、`BuildingUI.postsMarkup()`。

## 24.3 群像 LOD

群像从“和主角同一套高模”改为 **6 个 InstancedMesh 的低模资产**：

| 指标 | 优化前 | 优化后 |
|---|---|---|
| 群像三角形 | 449,200 | **155,200** |
| 全场景三角形 | 1,263,452 | **675,448** |
| 群像 draw calls | 6 | 6（不变，仍为实例化） |

低模保留：衣领、腰带、发髻、眼睛、眉毛、嘴；去掉：耳、鼻、手指、衣摆多层、发带、发簪、佩饰。
命名角色仍用高模 `createNpcAssets()`，只有远景群像使用 `createCrowdAssets()`。

## 24.4 玩家合批与最终 calls

玩家静态部件按 **材质** 合批，保留可动组：

- 合并：躯干、衣摆、腰带、护腕、面部、头发、剑鞘、剑身等静态直接子网格；
- 保留：左右臂、左右腿、头部、持剑手、背后剑、腰间鞘等 Group 的 transform，因此持剑/挥剑/头部微动不破坏；
- 玩家 mesh：**71 → 31**。

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 山门休眠 | 273-279 calls | **207 calls** |
| 山门试剑 | 324 calls | **257 calls** |
| 试剑三角形 | 1.26M | **330,326** |
| 玩家 mesh | 71 | **31** |

目标“试剑 ≤300 calls”已达成。

## 24.5 镜头、标记与无障碍

- 建筑 DOM 标记增加 `aria-label`，并在屏幕空间做 **标签碰撞避让**：两个标记过近时只显示先到的一个。
- 建筑标记字体从 9px 提到 10px；建筑驻派按钮、总览条目补 accessible name。
- 候选、事件、结算弹窗打开时，焦点移到第一个可操作按钮；`focus-visible` 有高亮描边。
- Toast 增加 `aria-live="polite"`；viewport 允许缩放（`maximum-scale=5.0`）。
- 支持 `prefers-reduced-motion`，减少动画/过渡。
- 镜头原有的地形/树/建筑遮挡收缩继续保留；被遮挡时隐藏主角，避免穿模。

## 24.6 回归测试

`prototype/tests/smoke.mjs` 使用 Playwright + 本地 Chrome，自动启动静态服务器，覆盖：

1. 启动无控制台错误；
2. 三候选、唯一性、主线延后、次日回归、跳过；
3. 建筑驻派、维护费、存档读档；
4. 9 幕人物线 + 终章；
5. 休眠 calls < 260、试剑 calls < 300、三角形预算；
6. 玩家 mesh < 40。

运行：

```bash
cd prototype
pnpm build
pnpm test:smoke
# 或指定端口 / Chrome：
TEST_PORT=4311 CHROME_PATH="/path/to/Chrome" pnpm test:smoke
```

本轮结果：**34 项检查全部通过**。
